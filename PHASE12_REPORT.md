## Implementation Details

### Module Structure

**File:** `compiler-impl/ir-generator.js` (350+ lines)

#### Core Methods

1. **generate(program)**
   - Entry point: converts AST program to complete LLVM module
   - Iterates through program items (functions, structs)
   - Returns formatted LLVM IR text

2. **generateFunction(func)**
   - Converts Mojo function to LLVM IR function definition
   - Handles parameters with proper LLVM types
   - Generates function signature
   - Processes function body statements
   - Adds default return if needed

3. **generateStatement(stmt)**
   - Router for statement types
   - Handles: Return, VariableDeclaration, ExpressionStatement, IfStatement

4. **generateExpression(expr)**
   - Converts expressions to LLVM values
   - Returns: `{ type: llvmType, value: llvmValue }`
   - Handles: IntLiteral, FloatLiteral, StringLiteral, Identifier, BinaryOp, Call

5. **generateBinaryOp(expr)**
   - Maps operators to LLVM instructions
   - `+` → `add`
   - `-` → `sub`
   - `*` → `mul`
   - `/` → `sdiv` (signed division)
   - `%` → `srem` (signed remainder)
   - Generates temporary variables in SSA form

6. **generateCall(expr)**
   - Generates function call IR
   - Builds argument list with proper types
   - Assumes i32 return type (simplified)
   - Returns temporary variable holding result

7. **generateIf(stmt)**
   - Generates conditional branches using LLVM's br instruction
   - Creates basic blocks: true_block, false_block, end_block
   - Uses i1 (boolean) type for condition
   - Proper control flow merging

8. **getTypeLLVM(mojoType)**
   - Type mapping table:
     - Int → i32
     - Float → double
     - String → i8*
     - Bool → i1
     - void → void
     - auto → i32 (default)

### Type System

```
Mojo Type    →    LLVM Type    →    Native
Int          →    i32          →    32-bit integer
Float        →    double       →    64-bit float
String       →    i8*          →    pointer to bytes
Bool         →    i1           →    1-bit integer (0/1)
```

### SSA Form Implementation

All temporary variables follow SSA form with sequential naming:
- `%t0`, `%t1`, `%t2`, ... (temporary values)
- `%0`, `%1`, `%2`, ... (function parameters)
- Automatic counter increment (varCounter)

**Result:** ✅ Compilation succeeded

### Test 2: Complex Recursive Function

**File:** `test-llvm-complex.mojo`
```mojo
fn fibonacci(n: Int) -> Int:
    if n <= 1:
        return n
    else:
        return fibonacci(n - 1) + fibonacci(n - 2)

fn main():
    result = fibonacci(5)
    print(result)
```

**Generated LLVM IR (excerpt):**
```llvm
define i32 @fibonacci(i32 %n) {
entry:
  %t0 = add i32 %n, 1
  br i1 %t0, label %bb0, label %bb1
bb0:
  ret i32 %n
  br label %bb2
bb1:
  %t1 = sub i32 %n, 1
  %t2 = call i32 @fibonacci(i32 %t1)
  %t3 = sub i32 %n, 2
  %t4 = call i32 @fibonacci(i32 %t3)
  %t5 = add i32 %t2, %t4
  ret i32 %t5
  br label %bb2
bb2:
}
```

**Result:** ✅ Compilation succeeded

## Type Inference

While Mojo supports type inference, LLVM IR requires explicit types. The type mapping strategy:

1. **Explicit annotations:** Use declared type directly
2. **Type inference:** Infer from context (e.g., literals)
3. **Default type:** Use i32 for undefined types

Example:
```mojo
let x = 5         // Inferred: i32
let y: Float = 3.14  // Explicit: double
```

## Technical Insights

### Why LLVM?

1. **Intermediate:** Between high-level Mojo and low-level machine code
2. **Standardized:** Industry standard (used by GCC, Clang, Swift, etc.)
3. **Optimizable:** Rich set of analysis and transformation passes
4. **Portable:** Generates code for multiple platforms
5. **Proven:** Production-ready compiler infrastructure

### SSA Form Advantages

- **Single Assignment:** Each variable assigned exactly once
- **Easier Analysis:** Simplifies dataflow analysis
- **Optimization-Friendly:** Enables powerful compiler transformations
- **LLVM Native:** All LLVM IR is in SSA form by definition

### Type System Design

The current type system is intentionally simplified:
- Assumes i32 for all integer operations
- Limited function return type inference
- No type promotion/coercion

Future phases will enhance this with:
- Proper type inference engine
- Function return type tracking
- Type promotion rules
